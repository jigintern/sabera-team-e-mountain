## 2026-08-28 のレビューで直したこと

段階5・6・UI はまとめて書いたので、実機に持っていく前に読み直した。

### 直した — 大気差を二重に掛けていた（**本物の不具合**）

`Geodesy.apparentDropM` が落ち込みに屈折係数 k=0.13 を掛けている（`(1-k)=0.87`）ので、
**地上の的の仰角はその時点で既に「見かけの仰角」**。そこへ稜線・山名・稜線合わせの 3 か所が
`apparentAltitudeDeg`（**星のための**大気差）をもう一度掛けていた。

**地平線で +0.48°・白山で +0.26° 上へずれ、低いほど強く効くので稜線の形が縦に 8% 縮んでいた。**
稜線合わせは「描いた形を実物に重ねる」ので、縦に縮んだ形は重ならない。
数字と歯止めは [76_terrain-measurements.md](team-e/76_terrain-measurements.md)。

`geo/Coordinates.kt` の `apparentAltitudeDeg` は**消していない**（星には正しい。呼ばないだけ）。

### 直した — 上限判定が実際に送る絵と違っていた

方位合わせの 2 段目で、`map.fitsBuffer` を数えた**あとに** `sightMark` が縦線を足していた。
縦線は行ごとに RLE の run を増やすので、**判定した絵より大きいものを送っていた**。
`bufferUsageBytes` は `lazy` なので、あとから読み直しても古い値が返る。印を描いてから数える順にした。

（余裕は 31KB あって印は 1KB 弱なので、**溢れて弾かれたことは無いはず**。順序だけが間違い）

### 直した — 6DoF が来る前に 1 枚送っていた

ヨーの初期値は 0 なので、稜線の画面に入った瞬間に**「北を向いた稜線」を 1 枚（0.4 秒）**出してから
正しい向きへ描き直していた。方位合わせの 2 段目も同じで、印に入れる前から見当違いの稜線が出ていた。
どちらも最初のサンプルを待つようにした。

### 足した — 方位マーク（N/E/S/W）

計画にあって入っていなかった。**方位合わせが合っているかを目で確かめる唯一の手段**なので入れた。
文字枠は山名で使い切るので**線で画像に焼く**。階調は 4（稜線は 7）。
`RidgeRenderer.render(cardinals = false)` で実機で比べられる。

### 直した — 粗合わせの結果が捨てられていた（**実機で必ず踏む**）

粗合わせ（スマホの十字・15 秒）が決まると山の一覧が出るが、**そこで山を選べないことは
十分ある**（鯖江で合わせに向く山は南東と北西で、白山の方角には無い）。
そのとき「合わせずに進む」を押すと、**いま測った方位が捨てられてオフセット 0 のまま**
稜線が出ていた。まるで違う方角の山が並ぶ。

出口を 1 本にまとめ、**途中で抜けても測れたぶんを必ず持ち出す**ようにした。
粗合わせが済んでいればボタンの文字も「ここまでで稜線を出す」に変わる。

### 直した — 「合わせた」と「合わせたつもり」の区別が消えていた

`fovMeasured` はアプリ側で**書かれるだけで読まれていなかった**ので、方位合わせの画面を
出た瞬間に「画角が実測か仮値か」が分からなくなっていた。粗合わせと稜線合わせも
同じ旗で立てていたので、**±5〜15° のままでも「合わせた」扱い**だった。

- 粗合わせ（`coarseDone`）と稜線合わせ（`headingAligned`）を別の旗にした
- 稜線の画面に「方位は粗合わせのまま（±5〜15°）／画角* は未実測の仮値 35°」を出す
- 画角の数字には実測でなければ `*` を付ける

### 直した — 画角の測定で 2 座目を強いていた（**取り違えの罠**）

`RidgeAlignment.fovDegFrom` は**峰 1 座と印の位置しか見ない**ので、2 座目は要らない。
首を振って同じ山を印へ寄せればよく、そのほうが取り違えない。
UI は 2 座目から 1 座目を除外していたので、**鯖江では白山を使えず**、
1.06° 隣の白山釈迦岳か 2.10° 隣の七倉山を選ぶしかなかった。

さらに **鯖江の白山そのものが方位合わせに向かない**ことが実データで分かった。
取り違えたまま合わせた較正は範囲外判定（10〜80°）にも掛からず「成功」として残る。
`PeakPanorama.confusable` を足して、UI が取り違えやすい山を下へ並べ替えて警告を出す。

**鯖江でいちばん安全な合わせ先は日野山**（167.55°・仰角 4.56°・9.6km）。
観測地ごとの表は [76_terrain-measurements.md](team-e/76_terrain-measurements.md)。
現地で出し直すには:

```
./gradlew :app:testDebugUnitTest --tests '*FieldNotesTest*' -i
```

### 確かめた — `alignment/` は星しるべから写し間違いなし

`YawDriftCorrector`（ヨー −44°/分 → 0.0°/分）・`CompassGate`・`HoldFeedback` は
**パッケージ名を除いて 1 文字も違わない**。`Compass` `Locator` `MagneticQuality`
`CalibrationEstimator` `HeadMotion` の差分は**コメントと `Site` → 緯度経度の引数化だけ**で、
計算は 1 行も変わっていない（偏角の足し込みも含めて確認）。

### 直していない — 先出し（減速中の描き直し）が未配線

`RedrawDecider.shouldPredict` と `HeadMotion`（テスト 14 件）はあるが、
**どの画面からも呼んでいない**。読んだ人が「動いている」と誤解しないよう、
定義側とこのファイルに書いた。

**意図して切ってある。** 外すと点滅が増える方向にしか転ばないので、
実機で「止めてから出るまでが遅い」と分かってから入れる。
入れる場所は `RidgeScreen` の追従ループ 1 か所（`shouldRedraw` の隣）。

## 踏んだこと

- **`applicationId` を分けると BLE の紐付けが引き継がれない。** 星しるべを上書きしない
  ために `jp.jig.sabera.app.minemiru` に変えたが、CompanionDeviceManager の association は
  アプリごとなので `connectToLastDevice` は何も見つけられない。**画面にグラスを選ぶ入口
  （`manager.showAutomaticSelectionDialog(activity)`）が要る。** これが無くて
  「送る」ボタンがずっとグレーアウトしていた
- **`LaunchedEffect` の中で例外が出るとボタンが永久に死ぬ。** 焼く処理が失敗すると
  `baking` が `true` のまま残り、画面には理由が何も出ない。`runCatching` で必ず戻すようにした

- **`build-peak-catalog.py` の百名山照合が名前だけだった。** 元データに「駒ヶ岳」は6座あり
  百名山は4座、「白根山」は2座で両方百名山。名前照合では秋田駒ヶ岳(1158m)まで
  百名山になっていた。**(山名, 標高) の組**に変えた（元データ1059件で衝突ゼロを確認）
- **近距離の地面が稜線を壊していた。** 鯖江から南に実地形に無い完全な水平線が出た。
  原因は 2 つ重なっていた — ①最近傍で標高を引いていたので 500m 先では 124m 画素1つが
  方位14°ぶんを占め、0.1°刻みのレイ140本が同じ値を返して階段になった ②観測者が
  地面より低いと平地そのものが壁になる（観測者0mで白山が **11.31°** に出た）。
  **双線形補間**と **`MIN_DISTANCE_M = 1000m`** で直した。白山は観測者 0〜100m で
  2.24〜2.34°（振れ幅 0.10°）に収まった。詳細は
  [76_terrain-measurements.md](team-e/76_terrain-measurements.md)
- **復元テスト 3 件が実装と食い違っていた。** うち 2 件は `altitudeDeg` の引数順
  （観測者と対象が逆）。1 件は「鯖江の真西は日本海なので地平線ちょうど」という
  **事実誤認**で、実際は丹生山地（16kmに588m・1.86°）が塞いでいて海は見えない
- **`material-icons-extended` で APK が 85MB になっていた。** debug ビルドには R8 が
  効かないので数千のアイコンが丸ごと dex に入る。1つも使っていないので外して **51MB**。
  実機へ何度も入れ直す段階でこの差は待ち時間として効く
- **`build-dem.py --verify` の下限 -100m が厳しすぎた。** 10/914/385（八戸付近の海岸）に
  元データが -121.85m を持っている。元 PNG と突き合わせて**配信元の値だと確認**し、
  しきい値を -200m にした。符号化の不具合ではない

- **山名に大気差を掛け忘れると、名前だけが山から浮く。** 稜線は
  `apparentAltitudeDeg` で持ち上げているので、**山頂も同じだけ持ち上げないと**
  0.48°（画面で約 7px）ずれる。復元されたコードは掛けていなかった。
  `build/ridge/panel-hinosan.png` で山頂の印が稜線の頂点に乗っているのがその確認

- **百名山の予約枠は 4。** 47 都道府県庁所在地 × 72 方位 = 3,384 視野で測り直した。
  押し出される山との仰角差は**中央値 0.10°・2°を超えた例は 0 件**で、予約はほぼ何も
  犠牲にしていない。出る百名山は N=3 で 857 座、**N=4 で 891 座**、N=7 でも 915 座なので
  4 で頭打ち。復元コードは `3`（未確定）と書いていたが [PLAN.md](PLAN.md) の 4 が正しかった。
  台帳は [76_terrain-measurements.md](team-e/76_terrain-measurements.md)

- **鯖江から白山を向くと 4 座が枠を取り、重なりで 2 座に減る**（白山・大日山が残り、
  七倉山・白山釈迦岳が落ちる）。**枠を取れた数と実際に出る数は違う**ので、
  解説の主役は必ず `shownPeaks` から選ぶ

- **画面の骨格は星しるべから借りられる。** `GlassesApp` の持ち方（画面の状態・戻るキー・
  瞬断の見張り・切断を 1 か所に集める）はそのまま通用した。星の中身が絡むのは
  `StarMapScreen`（3,652 行）だけで、**骨格は 600 行のほうに入っている**

- **「つながっている前提の画面」の差し替えは 1 か所にまとめた。** 星しるべは
  同じ分岐を 3 画面に書いていた（`CALIBRATION` `STAR_MAP` の中）。峰ミルは `WithClient` 1 つ

- **地平線の器は画面ではなくアプリが持つ。** 画面ごとに焼くと、方位合わせを終えた直後に
  もう一度 2.8 秒待たされる。`RidgeSession` を `MinemiruApp` に置いて両方へ渡す

- **稜線合わせで「どの山か」をアプリに当てさせない。** 粗合わせの誤差は ±5〜15° あるので、
  中央に近い山を自動で選ぶと平気で取り違える。**一覧から人に選ばせる**のが正しい。
  そのうえで `RidgeAlignment` は、印と山が逆側にある／画角が 10〜80° の外に出る答えを捨てる
