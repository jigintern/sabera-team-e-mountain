## 踏んだこと

- **`applicationId` を分けると BLE の紐付けが引き継がれない。** 星しるべを上書きしない
  ために `jp.jig.sabera.app.minemiru` に変えたが、CompanionDeviceManager の association は
  アプリごとなので `connectToLastDevice` は何も見つけられない。**画面にグラスを選ぶ入口
  （`manager.showAutomaticSelectionDialog(activity)`）が要る。** これが無くて
  「送る」ボタンがずっとグレーアウトしていた
- **`LaunchedEffect` の中で例外が出るとボタンが永久に死ぬ。** 焼く処理が失敗すると
  `baking` が `true` のまま残り、画面には理由が何も出ない。`runCatching` で必ず戻すようにした

- **`build-peak-catalog.py` の百名山照合が名前だけだった。** 元データに「駒ヶ岳」は6座あり
  百名山は4座、「白根山」は2座で両方百名山。名前照合では秋田駒ヶ岳(1158m)まで
  百名山になっていた。**(山名, 標高) の組**に変えた（元データ1059件で衝突ゼロを確認）
- **近距離の地面が稜線を壊していた。** 鯖江から南に実地形に無い完全な水平線が出た。
  原因は 2 つ重なっていた — ①最近傍で標高を引いていたので 500m 先では 124m 画素1つが
  方位14°ぶんを占め、0.1°刻みのレイ140本が同じ値を返して階段になった ②観測者が
  地面より低いと平地そのものが壁になる（観測者0mで白山が **11.31°** に出た）。
  **双線形補間**と **`MIN_DISTANCE_M = 1000m`** で直した。白山は観測者 0〜100m で
  2.24〜2.34°（振れ幅 0.10°）に収まった。詳細は
  [76_terrain-measurements.md](team-e/76_terrain-measurements.md)
- **復元テスト 3 件が実装と食い違っていた。** うち 2 件は `altitudeDeg` の引数順
  （観測者と対象が逆）。1 件は「鯖江の真西は日本海なので地平線ちょうど」という
  **事実誤認**で、実際は丹生山地（16kmに588m・1.86°）が塞いでいて海は見えない
- **`material-icons-extended` で APK が 85MB になっていた。** debug ビルドには R8 が
  効かないので数千のアイコンが丸ごと dex に入る。1つも使っていないので外して **51MB**。
  実機へ何度も入れ直す段階でこの差は待ち時間として効く
- **`build-dem.py --verify` の下限 -100m が厳しすぎた。** 10/914/385（八戸付近の海岸）に
  元データが -121.85m を持っている。元 PNG と突き合わせて**配信元の値だと確認**し、
  しきい値を -200m にした。符号化の不具合ではない
