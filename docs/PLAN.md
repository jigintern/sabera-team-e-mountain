## Context

`sabera-team-e` の**星しるべ**は、SABERA スマートグラスに星座を重ねる Android アプリ。その**山版**を `sabera-team-e-mountain` に新規に作る。

**この計画は2度目の挑戦。** 2026-08-27 の午前中まで、このディレクトリには 517 テスト合格・APK ビルド可の実装が存在したが、**すべて git 未追跡のまま 11:27〜13:32 の間に消去された**。Time Machine 未設定・GitHub 未 push・ローカル複製なしで、通常の復旧経路はすべて閉じている。

ただし Claude Code のセッションログから **Kotlin 25ファイル・Python 4本・テスト11本（計 88.7KB）が一字一句復元可能**で、`/private/tmp` に DEM タイル 3.6MB と山岳データも生存している。前回の設計文書（20決定・DEM 実測値・150km 上限の導出）も `~/.claude/plans/sabera-team-e-sabera-sabera-stateful-hanrahan.md` に完全な形で残っている。

**インターンは明日終了。** このアプリはメイン発表ではない。したがって本計画の成功条件はただ一つ — **明日の終わりに「SABERA のレンズ越しに、本物の山並みと重なった稜線」が実機で出ていること**。

### 星と山は座標系以外ほぼ何も共有しない

星は無限遠にあり、時間とともに動き、互いを隠さない。山は有限距離にあり、不動で、そして**互いを隠す**。この差が設計の大半を決めている。星しるべから引き継ぐ価値はコードそのものより、**実機で測って直した資産**にある。

- **ヨードリフト補正** — グラスに磁力計は無く、ヨーは静止中も 44°/分 流れる。`YawDriftCorrector` が 0.0°/分 まで潰してある。再現には実機と何日もかかる
- **投影パイプライン** — `sky/Coordinates.kt` に全ての符号規約が閉じ込めてある。ENU・北0°東回り・右手系・ステレオ投影 `r = 2tan(θ/2)`
- **大気差補正** — `apparentAltitudeDeg` は高度0°で約29′持ち上げる。**稜線はまさに高度0°付近に居る**ので、星より重要

### 段階3 — `geo/` `tile/` `terrain/` を TDD で書く（Android に触らない）

復元したテストを**先に置く**。これが仕様書になる。

- `geo/Geodesy.kt` — 大円距離・方位
- `geo/Coordinates.kt` — 星しるべ `sky/Coordinates.kt` を package 宣言だけ変えて移設。`Vec3` `Basis` `enu()` `project()` `projectionScale()` `apparentAltitudeDeg()` は**一切変更しない**
- `tile/DemTile.kt` `DemElevationSource.kt` — 自前形式の読み出し
- `terrain/Raycaster.kt` — 全方位 7,200本（0.05°刻み）のレイ。地球の丸みと大気差（屈折係数 k=0.13）を含む落ち込み：
  ```
  drop(d) = 0.87 × d² / (2 × 6,371,000)
  alt(d, h) = atan( (h − h_obs − drop(d)) / d )
  ```
  サンプル間隔は近距離100m・遠距離500m。**位置が確定したときに1回だけ**計算し、首の動きでは再計算しない。再計算の閾値は **50m 移動**（50km 先の山が画面1画素=0.066°動く距離が約57m）
- `terrain/PeakVisibility.kt` — 山ごとの個別レイマーチ。**地平線プロファイルの最大仰角だけでは足りない**（手前の低い尾根の上に、その裏の高い山より低く見えている山があり得る）
- `catalog/Peak.kt` — `peaks.json` の読み込み

**完了条件**: `./gradlew :app:testDebugUnitTest` が緑。特に **鯖江(35.9432, 136.1846, 標高50m) から白山＜御前峰＞(2702m, 57.8km) が仰角 2.40°±0.05°**、および **鯖江→日野山(794m, 9.6km, 仰角4.41°) が白山を隠す**遮蔽ケース。

### 段階4 — 稜線をグラスに出す 🎯 **絶対防衛線**

`glass/` から `GlassCanvas` `CanvasBudget` `RedrawPolicy` `GlassTextPage` `GlassTextArt` `BundledData` `GlassBrightness*` をコピー（**無改造**）。`StarMapInk` を `RidgeInk` に改名。`glass/RidgeRenderer.kt` を新規に書く。

レンダーループの骨格は星しるべから保存する：

```
プロファイル/山を alt/az へ → enu(az, alt) → project(v, basis, k, w, h)
```

| 要素 | 描き方 | 階調 |
|---|---|---|
| スカイライン | 太いストローク（3–5px） | **7（255）** |
| 方位（N/E/S/W） | ポリラインで自前描画（テキスト枠を節約） | 4 |

**塗りつぶさない。細線にしない。** 塗りは実景の山を隠す（黒＝透明の波導ディスプレイなので、光った画素は実物に重なる）。細線は屋外の空に負ける（星しるべの実測：2〜4px の点は背後の星と見分けが付かない）。答えは**最上段の階調(255)だけを使い、線幅を稼ぐ**。

星しるべの地平線の円は**描かない**。稜線がその役目を引き継ぐ。

**完了条件**: **実機のグラスに稜線が出る。** ここで「SABERA に山の稜線を表示するアプリ」が成立する。**即コミット。**

### 段階5 — 山名ラベル7枠

`glass/PeakLabels.kt` を書く。7枠のうち**日本百名山に優先枠4つ**（`FAMOUS_SLOTS = 4` — 前回 47都道府県庁所在地 × 72方位 = 3,384視野を実測して決めた値）、残り3枠を仰角順。

`glass/RidgeMap.kt` で**絵と名前を1つの容器で運ぶ**。星しるべの `StarMap.kt` の設計不変条件をそのまま守る — 別々に計算すると「オリオン座と表示しながら別の星座を喋る」事故（#37）が起きる。

**完了条件**: 実機で白山にラベルが乗る。

### 段階6 — 方位合わせ（稜線合わせ・画角の実測）

`alignment/` を丸ごとコピー（`YawDriftCorrector` `LookLatch` `HeadMotion` `MagneticQuality` `CompassGate` `HoldFeedback` `Locator` `Compass` `CalibrationEstimator`）。`ui/CalibrationScreen.kt`（859行・**実機確認済み**）を移植。

その上に `alignment/RidgeAlignment.kt` を新規に書く。2段構え：

1. **スマホ同期**（既存・実装済み）で ±10° まで
2. **稜線合わせ**（新規）で ±1° まで追い込む

星ではこれができない。星は点で、どれがどれか分からないため。**山の稜線は形が一意なので「描いた線を実物に重ねてください」が成立する。**

**副産物として画角が実測できる。** `ObservationDefaults.STAR_MAP_FOV_DEG = 35.0` は星しるべ自身が「開いている最大の不明点」に挙げている未実測の仮値。既知方位の2点が画面上で何画素離れるかから逆算できる。

既存の作法を踏襲：**確定はボタンではなく静止で取る**（押す動作そのものが精度を壊す）。

**完了条件**: 描いた稜線が実景と重なる。画角の実測値が `docs/team-e/70_measurements.md` に入る。

## ドキュメント

明日で終わるので最小限。**ただし `CLAUDE.md` `AGENTS.md` `docs/PLAN.md` `docs/STATUS.md` `CONTEXT.md` は段階0 で、コードより先に置く**（→「引き継ぎ」の節）。用語集は最小限とはいえ外せない — **用語がぶれると実装がぶれる**し、交代したエージェントが「稜線」と「尾根線」を取り違えると設計が崩れる。

星しるべの形式に合わせ `言葉 | 意味 | コード` の3列。**用語は素の日本語**（「レイキャスト」ではなく「見通し計算」）。

| 言葉 | 意味 | コード |
|---|---|---|
| **観測地** | 稜線の計算に使う緯度経度と標高。**星と違い、50m 動けば作り直しが要る** | `Locator` |
| **見通し計算** | 観測地から全方位へ地形をたどり、各方位でいちばん高く見える点を求めること | `terrain/Raycaster.kt` |
| **地平線** | 見通し計算の結果。方位ごとの仰角と、そこに立っている山 | `HorizonProfile` |
| **稜線** | 地平線をグラスに描いた線。**空と大地の境界そのもの**で、名前の無い丘も含む | `RidgeRenderer` |
| **隠れる** | 手前の地形に遮られて見えないこと。**隠れた山は描かない** | `PeakVisibility` |
| **同梱地形** | 端末が持っている全国の標高（画素124m）。**これだけで動く** | `data/dem/` |
| **焼き直し** | 観測地が変わって地平線を作り直すこと。**50m 動いたら** | `RidgeSession` |
| **方位合わせ** | スマホ同期で粗く、稜線を重ねて追い込む2段の較正 | `CalibrationScreen` / `RidgeAlignment` |

`AGENTS.md` は星しるべのものを持ち込んで山向けに直す（禁止事項と規約だけ・200行以内）。`CLAUDE.md` は星しるべでは `@AGENTS.md` を読ませるだけのスタブだが、**峰ミルでは引き継ぎの入口を兼ねる**。ADR は明日で終わる前提なので**書かない**。
